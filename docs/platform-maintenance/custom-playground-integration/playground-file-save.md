# 遊樂場檔案保存

這一頁聚焦外部自訂遊樂場在工作流設定之外，如何保存與讀回同一筆 Agent 底下的檔案包。若要看工作流設定欄位本身，請先看 [工作流保存與讀回](workflow-save-load.md)。

## 保存範圍

遊樂場檔案保存處理的是 `agentic_playground_bundle.zip` 這類外部服務自行打包的檔案內容。AI Hub 不解析壓縮檔內部結構，只負責確認使用者與 `agent_id` 權限，並簽發短效上傳或下載連結。

固定儲存位置：

```text
playground-agents/{agent_id}/bundle/agentic_playground_bundle.zip
```

## 保存流程

1. 外部遊樂場先取得或確認 `agent_id`。
2. 外部遊樂場呼叫 AI Hub 的檔案保存 API，要求短效上傳連結。
3. AI Hub 驗證使用者權限後，回傳上傳 URL、方法與必要標頭。
4. 外部遊樂場直接把壓縮檔上傳到 Azure 儲存體。
5. 外部遊樂場保存 Azure 儲存體回應，作為本次檔案保存結果。

## 讀回流程

1. 使用者重新開啟同一筆 Agent。
2. 外部遊樂場呼叫 AI Hub 的檔案讀回 API，要求短效下載連結。
3. AI Hub 驗證使用者權限後，回傳下載 URL。
4. 外部遊樂場直接從 Azure 儲存體下載壓縮檔。
5. 外部遊樂場交給 Agentic SDK 或相關檢索元件還原內容。

## 維護檢查重點

| 問題類型 | 優先檢查 |
| --- | --- |
| 無法取得上傳連結 | 使用者權限、`agent_id`、來源網域、AI Hub API 回應。 |
| 上傳失敗 | 上傳 URL 是否過期、必要標頭是否完整、Azure 儲存體回應。 |
| 無法取得下載連結 | 使用者權限、`agent_id`、檔案是否存在。 |
| 下載後無法還原 | 壓縮檔內容、外部遊樂場解包流程、Agentic SDK 還原結果。 |

當短效連結可簽發、Azure 儲存體可完成上傳下載，且外部遊樂場能用同一包檔案還原狀態時，遊樂場檔案保存流程才算成立。
